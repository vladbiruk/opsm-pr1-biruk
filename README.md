A.5. Ресурси з некоректною конфігурацією сертифіката

Випадок 1

curl -v https://expired.badssl.com

Очікувана помилка:

SEC_E_CERT_EXPIRED

Причина: сертифікат прострочений.

Випадок 2

curl -v https://wrong.host.badssl.com

Очікувана помилка:

SEC_E_WRONG_PRINCIPAL

Причина: ім'я в сертифікаті не відповідає домену.

Випадок 3

curl -v https://self-signed.badssl.com

Очікувана помилка:

SEC_E_UNTRUSTED_ROOT

Причина: сертифікат підписаний недовіреним центром сертифікації.

Контрольні питання
1. Скільки рядків діагностичного виводу передує отриманню даних сторінки?

Кількість залежить від конкретного виводу curl. Перед HTTP-відповіддю відображаються службові повідомлення про DNS, встановлення з'єднання, TLS та HTTP-запит.

2. Які рядки наявні у виводі A.1 і відсутні у A.2? Чим це зумовлено?

У A.1 є повідомлення, пов'язані з HTTPS, наприклад schannel та ALPN. У A.2 їх немає, тому що neverssl.com використовує звичайний HTTP без TLS-шифрування.

3. Звідки у виводі з'явилося значення 443, якщо його не було вказано в адресі?

Порт 443 є стандартним портом для HTTPS. Тому curl автоматично використовує його, якщо порт не вказаний в URL.

4. Як змінилося значення TTL між двома запитами A.3? Що означає це число?

TTL — це час, протягом якого DNS-запис може залишатися в кеші. Під час повторного запиту його значення зазвичай зменшується, якщо запис не був оновлений.

Висновки
D.1. Що виявилося неочевидним або несподіваним

Під час виконання практичної роботи було цікаво побачити, що звернення до icann.com не закінчується просто отриманням HTML-коду. Спочатку система повинна визначити IP-адресу домену за допомогою DNS, після чого встановлюється мережеве з'єднання та виконується перевірка HTTPS.

Для icann.com DNS повертає IPv4-адресу 192.0.43.22 та IPv6-адресу 2001:500:88:200::22. Це показує, що одне доменне ім'я може бути пов'язане одразу з кількома типами IP-адрес.

Також цікавим є перенаправлення з icann.com на https://www.icann.org/. Тобто сервер може відповісти не самою сторінкою, а повідомленням про те, що ресурс знаходиться за іншою адресою. Це демонструє роботу HTTP-кодів перенаправлення.

Порівняння HTTPS із HTTP через neverssl.com показало, що при HTTPS додатково виконуються операції, пов'язані з TLS та перевіркою сертифіката. У випадках із некоректними сертифікатами curl припиняє встановлення захищеного з'єднання.

D.2. Чому саме така кількість груп у частині B

Я виділила 5 груп, оскільки вони показують послідовність звернення до вебресурсу: спочатку відбувається DNS-розпізнавання імені, потім встановлення з'єднання, перевірка захисту, HTTP-обмін і, нарешті, отримання вмісту вебсторінки. Такий поділ дозволяє окремо побачити основні етапи взаємодії користувача з вебресурсом.
